IMPORTANT DEMO BOUNDARIES

All data is synthetic. The upstream assistant is a mock. The security classifier is offline/heuristic, not an LLM. No real emails, bank transfers, private customer records or external model calls are involved.

  1. 00–15s

    A normal request still works.

    A harmless KYC-document question returns HTTP 200 with an ALLOW decision.

  2. 15–30s

    Sensitive input is handled separately.

    A published synthetic test identifier returns HTTP 200 with REDACT, governed by the pii.pesel control. It is a test fixture, not a real person's record.

  3. 30–45s

    An injection attempt is blocked.

    The request to ignore instructions and reveal the system prompt returns HTTP 403 with BLOCK under injection.heuristic.

  4. 45–60s

    Check the evidence.

    The isolated audit verification endpoint returns HTTP 200 with ok=true. This validates the recorded chain, not perfect security or production certification.

Why this matters to a technical buyer

The example makes request handling, policy checks, explicit failures and auditability inspectable. It is evidence of an engineering approach, not a guarantee that all attacks are detected.
